# External URL Audit

审计日期：2026-09-22

本清单覆盖源码、正式文档、工作流和测试中出现的外部 URL。重点是下载源、GitHub API 端点、仓库链接和许可证链接；`package-lock.json` 中的依赖 tarball URL、测试故意使用的假 URL，以及历史验证报告里的已过期固定版本 URL 单独分类，不把它们误当作当前安装源。

## 结论

- 当前运行时没有硬编码 Claude/Codex 的具体版本下载链接。
- 当前运行时统一通过 `install-all.js` 请求 GitHub Release API `releases/latest`，使用 API 返回的 `size` 和 `digest` 做完整性校验。
- Windows 和 macOS Claude/Codex 都使用上游项目 Release 说明中提供的官方 CDN 短链。
- `install-cc-switch.js` 没有独立的下载逻辑；它只筛选 CC Switch 配置并委托 `install-all.js`。
- `macos-installer.js` 不请求上游 URL；它只挂载并校验已经由 `install-all.js` 下载到本地的 DMG。
- Git 历史显示，错误域名在初始上传提交 `fd32ed1` 中先进入 `software-manifest.js`，README 在 `8024c32` 中随后写入同一组域名；没有提交证据表明它们来自 GitHub Release API 或经过可访问性验证。

## 非运行时 URL 分类

| 范围 | 处理结论 |
|---|---|
| `docs/superpowers/` 中的固定版本 Release、asset redirect、`downloads.claude.ai` 和 `api.anthropic.com` URL | 历史可行性/实机验证记录。它们保留当时验证证据，不作为当前 manifest 或运行时下载配置；当前代码已改为动态 GitHub Release API |
| `package-lock.json` 中的 `https://registry.npmjs.org/...` | npm 锁文件依赖来源，不是软件安装源；URL 形态与锁文件用途一致，不参与安装器运行时下载 |
| `scripts/build-macos-dmg.js` 中 Apple PropertyList DTD URL | 构建时 XML 声明，不是网络下载端点 |
| 测试中的 `example.com`、`example.invalid`、假 GitHub Release URL | 故意构造的错误路径、重定向和校验夹具，不会进入运行时 manifest |
| `release-assets.githubusercontent.com` 固定地址 | 历史 HTTP 实测中记录的 GitHub 重定向最终地址；不硬编码、不作为当前配置 |

## 之前错误判断的更正

之前将 `claudeapp.agentsmirror.com` 与 `codexapp.agentsmirror.com` 判定为“不可用/不准确”没有足够证据。旧代码的路径 `/latest/win-x64`、`/latest/win-arm64` 和 `/latest/checksums` 本身并不是凭空拼接；结合上游 Release 说明，它们是官方 R2 CDN 短链。之前的问题是把“没有完成来源核验、网络环境可能访问失败、README 与第三方声明不一致”错误地合并成了“域名本身无效”。

当前实现已恢复 Windows CDN 路径，并保留 GitHub Release API 作为版本、资产大小和 SHA-256 digest 的校验来源。若 CDN 返回的文件与 API 最新 Release 资产不一致，安装器会因大小或哈希校验失败而拒绝安装。

## 核对边界

本次环境完成了源码、Git 历史、manifest/API 解析逻辑和既有真实 GitHub API 响应的核对；之前批量逐 URL `curl -I` 请求曾被网络审批限流（HTTP 429），所以不能把那次网络限制当作域名无效的证据。当前回归测试锁定了三个 `releases/latest` API、两个官方 CDN 域名、平台路径以及 API size/digest 校验关系。
